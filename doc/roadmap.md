### 아직 안 함

- 개별 셀 단위 참조 (`Table.Field#Index` 형태로 특정 셀을 가리키는 기능)
- 히스토리 **백필**. 기능이 생기기 전 커밋들은 채우지 않습니다 — 그 구간의 변경은 다음 스냅샷에 뭉치고, 뭉쳤다는 사실은 리포트에 표시됩니다.
- **스큐 하네스를 나머지 12개 언어로.** [스키마 진화](binary-format.md)의 교차 읽기 게이트가 지금 C#만 돌립니다. 값 읽기는 적합성 코퍼스가 전 언어를 덮지만, 모르는 컬럼 건너뛰기와 타입 승격을 **실제로** 확인한 것은 C#입니다.
- **컬럼 단위 압축.** 형식의 `flags` 바이트와 wire의 예약 비트가 자리를 비워두고 있고, 컬럼이 연속 블록이라 붙이기 싸지만 아직 아무것도 읽거나 쓰지 않습니다.

### 하지 않기로 함

- **`foreign[]` (가변 개수 참조).** 로우마다 개수가 다른 참조를 해석하려면 생성되는 리더가 로드 후 연결 단계에서 길이가 다른 배열을 다뤄야 하는데, 지원 언어들에 그런 형태가 없습니다. 조용히 해석되지 않는 코드를 뱉는 대신 명시적으로 거부하고, 고정 개수가 필요하면 `SerialField`를 쓰도록 안내합니다.
- **TypeScript 외의 언어에 JSON 읽기.** 바이너리가 런타임 형식이고 JSON은 산출물입니다. 되읽으려면 .NET의 `datetime`·`timespan`·`uuid` 텍스트 형식을 언어마다 손으로 파싱해 바이너리 경로와 같은 값에 도달해야 하는데, 어긋나면 실패하지 않고 값이 달라집니다. 사람이 보는 용도는 Html 타깃이, 변경 추적은 히스토리가 대신합니다. 특정 언어에서 필요해지면 그 언어에만 코퍼스 게이트와 함께 넣습니다. 자세한 이유는 「[왜 바이너리만인가](languages/readme.md#왜-바이너리만인가-typescript만-예외인가)」에 있습니다.

- **타깃을 외부 어셈블리에서 로드하는 플러그인 구조.** 버전 간 안정적인 계약을 유지해야 하는데, 타깃이 전부 이 저장소 안에 있는 도구에는 값이 없습니다. 타깃 등록은 실행 어셈블리 스캔으로 합니다.

- **생성 폴더 구조 통일.** 런타임(리더 + 업데이터)은 **13개 언어 전부** `sheetman/` 아래에 있습니다 — C#·Python·Rust가 마지막이었고, Rust는 `src/sheetman/mod.rs`로 묶어 `sheetman::updater`가 되게 했습니다. 타입 파일은 `tables/`·`enums/`·`constants/`로 나눕니다 — C#·TypeScript·Kotlin·Ruby·PHP·Dart에 이어 **C와 C++**까지. C·C++는 `#include` 줄이 파일 경로와 **같은 헬퍼에서** 나오므로 둘이 어긋날 수 없고, 이름의 접근자 접두어는 남겨두었습니다 — 두 생성물을 한 include 경로에 두었을 때 부딪히지 않게 하는 것은 폴더가 아니라 그 접두어입니다.

  **평평한 채로 둔 네 언어는 이유가 하나입니다 — 그 언어에선 디렉터리가 곧 패키지/모듈입니다.** Go는 하위로 내리면 내부 필드를 전부 export해야 하고, Python은 `tables/` 패키지가 접근자 `tables.py`를 가려버리며, Rust는 접근자 모듈이 이미 `tables`라 부딪히고, Java는 모든 생성 타입의 임포트 경로가 바뀝니다. Kotlin만 JVM 중에서 예외인 것은 패키지와 경로를 따로 둔 언어이기 때문입니다. Unreal은 엔진이 `Public/`·`Private/`를 요구합니다.

  선행 조건이었던 **마커 문제도 함께 고쳤습니다.** 런타임 파일은 `lib/`에서 그대로 복사되느라 `Generated by SheetMan` 헤더가 없었고, 그래서 sweep이 지우지 못해 **이름이나 위치를 바꾸면 옆 이름이 소비자 프로젝트에 영원히 남았습니다.** 이제 배너를 쓸 때 붙입니다 — `lib/`의 원본은 생성물이 아니므로 거기에 적지 않았고, PHP의 `<?php`와 Ruby의 `frozen_string_literal`만 그 뒤에 넣습니다. 이번에 옮긴 파일들이 실제로 스윕되는 것으로 확인됐습니다
- **TypeScript 참조 연결.** `solveCrossReferences`가 **빈 메서드**로 생성되고 있었습니다 — 레코드마다 있는 `setReference_*_INTERNAL`을 부르는 곳이 어디에도 없어서, 바이너리에서 읽으면 참조가 `undefined`이고 JSON에서 읽으면 **레코드 타입으로 선언된 멤버에 숫자 키가** 들어갔습니다. 왕복 테스트가 테이블을 하나씩 읽고(그 경우 연결되지 않는 것이 정상) 원시 키만 비교했기 때문에 잡히지 않았습니다. 연결 단계를 구현했고, 접근자에 `readAllBinarySync`를 더해 바이너리도 전부 읽고 연결할 수 있게 했으며, 왕복 테스트가 이제 두 경로의 **해석된 참조**를 비교합니다
- **데이터 갱신기 — 13개 언어 전부.** C# 설계 그대로이고, 열 개 언어는 표준 라이브러리만 씁니다. 언어마다 없는 것을 그 파일 안에서 채웠습니다: MD5가 없는 Dart·Rust·C·C++에는 MD5를, JSON 파서가 없는 Java·Kotlin·Rust·C·C++에는 매니페스트용 파서를 함께 넣었습니다. PHP는 `ext-curl`로 쓰다가 게이트를 돌린 인터프리터가 `curl_init()`을 모른다고 답해 **코어 HTTP 스트림 래퍼로 바꿨습니다.** **외부 의존은 세 언어뿐이고 모두 명시되어 있습니다** — Rust는 `ureq` 하나를 생성되는 `Cargo.toml`에, C·C++는 libcurl 하나를 링크 플래그로. 켜지 않으면 세 언어의 생성물도 여전히 자립적입니다. 언어당 `<Lang>UpdaterTests`가 실제 툴체인으로 실제 HTTP 서버에 붙어 재시도·해시 거부·404 비재시도를 확인하고, 직접 쓴 MD5는 공개 벡터로 따로 확인합니다
- **레코드 조회 API 통일 — 13개 언어 전부.** 인덱싱된 필드마다 `FindBy<Field>` · `GetBy<Field>OrThrow` · `Contains<Field>`를 언어 표기 관례로 냅니다. 이전에는 C#과 TypeScript만 그랬고 나머지 11개는 기본 인덱스의 `find` 하나뿐이라, 시트에서 `*`로 지정한 **보조 인덱스가 11개 언어에서 아예 닿지 않았습니다.** 이름이 바뀐 것이 아니라 기능이 생긴 것입니다 — 언어마다 인덱스별 맵(C는 정렬 배열)을 만들고, 키 타입을 그 컬럼의 타입에서 가져옵니다. 던질 것이 없는 C와 Unreal은 두 함수만 냅니다. 참조 해석도 대상 테이블의 **기본 인덱스 함수 이름을 읽어서** 부르므로, 첫 컬럼 이름이 `index`가 아닌 시트에서도 맞습니다. 자세한 것은 [언어별 가이드](languages/readme.md#레코드-조회--같은-세-함수-13개-언어에서-같은-이름)에 있습니다
