# uwo 레이아웃 분석

> [문서 목록으로](../readme.md)

2026-08-08. 라이브 서비스 중인 `uwo`의 엑셀 데이터와 자체 익스포트 툴(`CMSExportApp`)을 조사하고,
`sheetman` 레이아웃과의 차이를 정리했습니다. 워크북은 [samples/uwo/](../samples/uwo/)에 사본으로 두었습니다.

> 이 문서는 **아직 변환하지 않은 상태의 분석**입니다. [rescue 적용 기록](adopting-a-project.md)이 그랬듯,
> 변환을 실제로 돌린 뒤에 「걸린 것」과 「산출물 대비」를 이 문서에 덧붙입니다.

---

## 1. 왜 볼 만한가

`rescue`는 규모가 작고(테이블 67개, 10만 행) **아직 서비스하지 않는** 프로젝트였습니다.
`uwo`는 반대쪽 극단입니다 — 라이브 서비스 중이고, 데이터가 385MB이고,
익스포트 결과가 서버·클라이언트 양쪽으로 나가며, 지역별 빌드 변종까지 있습니다.

그리고 결정적으로, **레이아웃이 `sheetman`과 닮았지만 같지 않습니다.**
`rescue`는 「시트 탭 하나 = 테이블 하나」라는 단순한 규칙이라 우리 모델의 부분집합이었습니다.
`uwo`는 시트 한 장에 테이블을 여럿 놓고, 컬럼마다 서버/클라를 가르고, 컬럼 이름으로 중첩 구조를 만듭니다 —
**우리가 가진 것과 겹치면서, 우리에게 없는 것도 가지고 있습니다.**

## 2. 규모

|항목|값|
|--|--|
|워크북|29개 (`.xlsx` 13 · `.xlsb` 13 · `.xlsm` 3)|
|입력 크기|385.5 MiB|
|익스포트되는 테이블|**615개** (데이터 테이블 581 + 타일 34). 그중 95개가 `_BCCN` 지역 변종|
|익스포트 컬럼|최상위 프로퍼티 8,718개 — 평평한 7,889 · 배열 745 · 객체 84. 타입이 붙은 리프 10,247개|
|산출물|클라이언트 736개 파일 394MB · 서버 742개 파일 387MB · textset 597개 파일|
|검증 스크립트|Lua 141개|

가장 큰 워크북 하나가 `UWO_테이블.xlsb`로 **시트 140장, 테이블 144개**입니다.
`Shop` 한 테이블이 29,885행, `WorldPassive`가 21,369행입니다.

> 입력 385.5 MiB 중 **195.3 MiB가 `UWO_기후.xlsx` 한 개**로 절반입니다. 그런데 이 워크북에서 익스포트되는 테이블은 없습니다 — §7 참조.
>
> [samples/uwo/](../samples/uwo/)의 사본은 그래서 35개 128.6 MiB입니다. 익스포트되는 테이블이 0개인 워크북 셋을 뺐고, 변환 대상은 하나도 줄지 않았습니다 — [무엇을 왜 뺐는지](../samples/uwo/readme.md).

## 3. 파이프라인

```
xls/*.xlsx|xlsm|xlsb
   → CMSExportApp (EPPlus / xlsb는 LinqToExcel+ACE OLEDB)
   → 워크북 「정의된 이름」마다 ClassDescriptor 하나
   → client/<Table>.json · server/<Table>.json · textset/<Table>.txt
   → validation/*.lua (luajit) 로 사후 검증
```

우리와 갈라지는 지점이 둘 있습니다.

- **코드를 만들지 않습니다.** 산출물은 JSON뿐이고, `Template/ClassTemplate.txt`가 있긴 하지만
  `Newtonsoft.Json` 어트리뷰트를 붙인 POCO 하나를 찍는 수준입니다. 읽는 코드는 게임 쪽에서 손으로 씁니다.
- **검증이 익스포트 밖에 있습니다.** 익스포터는 키 중복·키 범위·타입 파싱만 보고,
  나머지(필수값·최소/최대·enum 화이트리스트·참조 존재·에셋 존재)는 **익스포트가 끝난 JSON을 Lua가 다시 읽어** 검사합니다.
  그래서 잘못된 데이터가 담긴 JSON이 일단 만들어지고, 그 다음에 검사됩니다.

## 4. uwo 레이아웃 규격

### 4.1 테이블의 경계 = 워크북의 「정의된 이름」

`sheetman`은 마커(`~~table:Item~~`), `rescue`는 시트 탭 이름으로 테이블을 찾습니다.
`uwo`는 **엑셀의 정의된 이름(defined name / named range)** 이 테이블 하나입니다.

```
Guild        = Guild!$A$1:$G$18
MainMenu     = MainMenu!$A$2:$F$30
MainMenu_BCGL = MainMenu!$G$2:$L$30      ← 같은 시트, 오른쪽에 두 번째 테이블
```

- **테이블 이름 = 정의된 이름.** 시트 탭 이름은 아무 역할이 없습니다.
- **시트 한 장에 테이블 여럿을 놓을 수 있습니다.** 실제로 `MainMenu`/`OceanDoodad`/`OceanDoodadAreaSpawner`/`WorldTile`
  네 시트가 지역 변종을 오른쪽에 나란히 두고 있습니다. `sheetman`이 마커로 하는 일을 이름 영역이 합니다.
- 이름에 `_xl` 또는 `!_`가 들어가면 건너뜁니다 — 엑셀이 만드는 `_xlnm._FilterDatabase`, `_xlfn.*`을 걸러내려는 규칙입니다.
- **워크북 범위 이름만 봅니다**(EPPlus 경로). 시트 범위 이름은 무시되므로,
  `LoadingPage!Extract`나 `Transcendence!MateTraining`처럼 **테이블처럼 보이는데 익스포트되지 않는** 이름이 존재합니다.

### 4.2 헤더 2행 + 개수가 정해지지 않은 스키마 행

이름 영역 안에서의 좌표입니다 (시트 절대 행이 아닙니다).

```
r1        프로퍼티 이름       ← 빈 칸이면 그 컬럼은 제외
r2        타입               ← 아래 §4.3
r3..rN    스키마 행          ← 첫 컬럼이 ':'로 시작하는 행. 개수와 순서가 테이블마다 다릅니다
rN+1..    데이터
```

실물입니다 (`UWO_상회.xlsx` : `Guild`).

```
r1  | id            | level  | exp    | expStack | maxUser | makeShipPartsLevel
r2  | key:0~200     | number | number | number   | number  | number
r3  | :required     | 1      | 1      | 1        | 1       | -
r4  | :min          | -      | -      | -        | -       | 0
r5  | :max          | -      | -      | -        | -       | 5
r6  | :enum         | -      | -      | -        | -       | -
r7  | :links        | -      | -      | -        | -       | -
r8  | 1             | 1      | 98400  | 98400    | 30      | -
```

**스키마 행은 위치가 아니라 첫 칸의 `:이름`으로 식별됩니다.** 그래서 개수가 테이블마다 다릅니다 —
`Guild`는 5줄이고 `GuildCraft`는 `:requiredInObject`가 하나 더 붙어 6줄입니다.
데이터 시작 행이 테이블마다 7행·8행·9행으로 갈리는 이유가 이것입니다.

|스키마 행|하는 일|쓰는 테이블 수|
|--|--|--|
|`:required`|이 컬럼은 값이 있어야 한다|580|
|`:min` / `:max`|숫자 범위. 참조 ID의 대역을 적는 데도 씁니다|581 / 581|
|`:enum`|허용 값 화이트리스트|579|
|`:links`|다른 테이블 참조. `"Mail"` 또는 `"ShipSlot","CEquip","Item"`처럼 **여러 대상**|576|
|`:link`|`Json/TableName` 형태의 단일 참조 (구형)|2|
|`:requiredInObject`|중첩 객체가 존재할 때만 그 안에서 필수|216|
|`:asset`|값이 언리얼 에셋 이름이다 → 실제 존재 확인|89|
|`:type`|익스포터가 자동 생성. 시트에는 없습니다|581|

이 블록은 산출물 JSON의 맨 앞에 `":TableName"` 키로 그대로 실려 나가고, Lua 검사기가 그것을 읽습니다.

> **`sheetman`에 없는 것이 여기 다 모여 있습니다.** 우리는 인덱스 유니크·참조 존재·순환 참조를 보지만,
> 필수값·범위·화이트리스트·에셋 존재는 보지 않습니다. uwo는 그것을 **시트 안에 선언**해 두었습니다.

### 4.3 타입 표기

타입 칸은 `타입[:부가정보]`입니다.

|타입|의미|출현|`sheetman` 대응|
|--|--|--|--|
|`key`|기본 인덱스. `key:2000~3999`로 허용 대역을 붙일 수 있습니다|574|`index` (대역 표기 없음)|
|`strkey`|문자열 기본 인덱스|7|없음 — 보조 인덱스로 강등해야 함|
|`number`|숫자. **정수/실수를 구분하지 않고** 셀 값을 JSON에 그대로 씁니다|7,926|`int` / `bigint` / `float` / `double`|
|`string`|문자열|640|`string`|
|`text`|**로컬라이즈 대상** 문자열. textset으로 함께 수집됩니다|580|없음|
|`bool`|참/거짓|445|`bool`|
|`bit`|**2진 문자열**. `1111111` → `Convert.ToInt64(v, 2)` = 127|70|없음|
|`float`|`Double.Parse` 후 기록|4|`float` / `double`|
|`[number]` 등|`[string]` `[text]` `[number]` `[float]` `[bool]` — 셀 하나에 여러 값|1|`T[]`|
|`-`|이 컬럼 무시|—|`#` 접두|

부가정보는 두 갈래입니다.

- **서버/클라 분리** — `string:c`는 클라이언트만, `number:s`는 서버만, 생략하면 양쪽.
  판정은 문자 포함 검사입니다(`tokens[1].Contains('c')`).
- **키 대역** — `key:min~max`. 단, 이 해석은 **프로퍼티 이름이 정확히 `id`이고 타입이 `key`일 때만** 적용됩니다.
  그 밖의 컬럼에 `:`가 붙으면 전부 서버/클라 표기로 읽히므로, 이름이 `id`가 아닌 키 컬럼에
  대역을 적으면 `0~200`에 `s`도 `c`도 없어서 **그 컬럼이 양쪽 산출물에서 조용히 사라집니다.**

### 4.4 컬럼 이름이 JSON 경로다

가장 큰 차이입니다. 프로퍼티 이름에 `[...]`를 쓰면 그 컬럼들이 **중첩 구조로 접힙니다.**

```
r1 | id | nationId | character[0]["Id"] | character[0]["Name"] | character[1]["Id"] | character[1]["Name"]
r2 | key:…        | number | number    | text                 | number             | text
```

```json
"character": [
  { "Id": 21000001, "Name": "…" },
  { "Id": 21000002, "Name": "…" }
]
```

- `name[0]` — 스칼라 배열. `patrolBuilding[0..2]`, `townId[0..16]`처럼 씁니다.
- `name[0]["Key"]` — **객체의 배열**. 대괄호 안이 숫자면 배열 인덱스, `"따옴표"`면 객체 키입니다.
- 깊이 제한이 없습니다. `[...]`가 나온 개수만큼 중첩됩니다.
- 배열 인덱스는 0부터 빈 곳 없이 이어져야 합니다 (중간이 비면 오류).

전체 8,718개 최상위 프로퍼티 중 **745개가 배열, 84개가 객체**이고, 그 안의 리프가 1,582개입니다.
**약 10%가 평평하지 않습니다.** 스키마 행도 같은 모양으로 중첩됩니다 (§4.2의 `:requiredInObject`가 그래서 필요합니다).

`sheetman`의 `SerialField`가 겉보기에 비슷하지만 접히는 결과가 다릅니다 —
`Slot1`·`Slot2`는 **스칼라 배열 하나**가 되고, 여기서는 **레코드의 배열**이 됩니다.

### 4.5 행·컬럼 제외와 「빈 값」

|규칙|동작|
|--|--|
|r1의 프로퍼티 이름이 빈 칸|그 컬럼 제외. **한글 설명 컬럼을 데이터 컬럼 사이사이에 끼우는 용도로 쓰입니다**|
|타입이 `-`|그 컬럼 제외|
|첫 컬럼(키)이 빈 칸|그 행에서 멈춤 — 테이블의 끝으로 봅니다|
|첫 컬럼이 `#`으로 시작|그 행 건너뜀 (행 주석)|
|셀 값이 `-`|그 프로퍼티를 **JSON에 아예 넣지 않음**. 빈 칸은 오류이고 `-`가 「없음」입니다|
|키가 `:`로 시작|데이터가 아니라 스키마 행 (§4.2)|
|`text` 값이 `@`나 `#`으로 시작|textset 수집에서 제외. `#`은 앞에서 떼어냅니다|

「빈 칸은 오류, `-`가 없음」이 우리와 정반대입니다. `sheetman`은 빈 셀을 기본값·빈 배열로 받습니다.
uwo는 **적는 것을 잊은 것과 없다고 적은 것을 구분하려고** 그렇게 했습니다.

### 4.6 `_BC` 빌드 변종

`Admiral_BCGL`, `SailCrest_BCCN`, `Shop_BCGL` …

|규칙|내용|
|--|--|
|파일 이름|`Admiral_BCGL.json` — 접미사가 붙습니다|
|JSON 안의 테이블 이름|`Admiral` — `LastIndexOf("_BC")` 이후를 **잘라냅니다**|
|고르는 시점|검증·로드 때 `BinaryCode`(`KR`/`GL`/`CN`)와 맞는 것을 씁니다. 접미사 없는 원본이 있으면 그쪽 우선|

즉 **같은 테이블의 지역별 대체본**입니다. 615개 산출물 중 95개가 `_BCCN` 짝입니다.
`sheetman`의 `TargetSide`는 서버/클라 두 갈래뿐이라 이 축이 없습니다.

### 4.7 타일 테이블

`ExportType.Tile`은 완전히 다른 산출물입니다. 헤더도 키도 없고, 이름 영역 전체를 정수 격자로 읽어
`{"WaterMapTile":{"x":250,"y":100,"t":[[…],[…]]}}`를 만듭니다. 34개가 이 형태입니다
(`OceanTileEditor.xlsx`의 이름 영역은 전부 `$A$1:$IP$100`).

## 5. 세 레이아웃 비교

|축|`sheetman`|`rescue`|`uwo`|
|--|--|--|--|
|테이블 경계|마커 `~~table:X~~`|시트 탭 = 테이블|**워크북 정의된 이름**|
|시트 하나에 여럿|가능 (마커로)|불가|**가능 (이름 영역으로)**|
|헤더 행|이름 / 타입 / target-side|주석 / 이름 / 타입 (3행 고정)|이름 / 타입 + **가변 개수 스키마 행**|
|컬럼 설명|`Field.Comment` (주석 행)|주석 행|**빈 이름 컬럼을 사이에 끼움**|
|기본 인덱스|`index`, `int`, 유니크|첫 컬럼|`key` (+`key:min~max` 대역) / `strkey`|
|보조 인덱스|`*Name`|없음|없음|
|enum|엔티티로 선언 (`~~enum:~~`)|`TableEnums` 시트|**없음** — `number` + `:enum` 화이트리스트|
|상수셋|있음|없음|없음|
|참조|`foreign`, 단일 대상, 정적 검증|없음|`:links`, **다중 대상**, Lua 사후 검증|
|배열|`T[]` + `SerialField`|`intArray` 등|`[T]` + `name[i]` + **`name[i]["k"]` 객체 배열**|
|중첩 객체|없음|없음|**있음 (깊이 무제한)**|
|서버/클라|마커·필드·recipe 3단|없음|타입 칸의 `:s`/`:c`|
|지역 변종|없음|없음|**`_BC{KR,GL,CN}` 접미사**|
|로컬라이즈|`string` (별도 처리)|없음|**`text` 타입 + textset 자동 수집**|
|빈 셀|기본값/빈 배열|기본값|**오류. 「없음」은 `-`**|
|행 주석|—|`#`/`//` 접두|`#` 접두|
|와이어 태그|`@N`|없음|없음|
|값 검증|인덱스·참조·순환|같음|필수·범위·화이트리스트·참조·에셋 (**Lua, 익스포트 후**)|
|산출물|13개 언어 + 바이너리·JSON·HTML|같음|**JSON만**|

## 6. 우리 코어에 없는 것

변환을 시도하면 부딪히는 순서대로입니다. 앞의 셋이 새 기능이고, 나머지는 매핑으로 풀립니다.

|무엇|왜 매핑으로 안 되는가|
|--|--|
|**중첩 컬럼** (`name[i]["k"]`)|`Model`에 「레코드의 배열」인 필드가 없습니다. 829개 최상위 컬럼이 여기 걸립니다. 평평하게 펼치면(`Character0Id`) 변환은 되지만 생성되는 API가 시트와 다른 모양이 됩니다|
|**`bit` 타입**|2진 문자열을 `long`으로 읽는 타입이 없습니다. `bigint`로 받되 파서에 진법을 알려줄 방법이 필요합니다|
|**컬럼 제약** (`:required` `:min` `:max` `:enum` `:asset`)|우리 정적 검증에 해당 항목이 없습니다. 없어도 변환은 되지만, **그러면 uwo가 지금 잡고 있는 것을 우리가 못 잡습니다** — 도구를 바꾸는 이유가 사라집니다|
|**다중 대상 참조** (`:links`에 3개)|`foreign`은 단일 대상입니다. 대상이 여럿이면 우리 참조 해석이 어느 테이블의 레코드를 물릴지 정할 수 없습니다|
|`_BC` 지역 변종|`TargetSide`와 같은 축이 아닙니다. 「같은 테이블의 대체본」이라는 개념 자체가 없습니다|
|`text` / textset|`string`으로 읽으면 값은 맞지만 textset이 안 나옵니다. 언리얼 `NSLOCTEXT` 목록이 빌드에 쓰입니다|
|정의된 이름 기반 경계|**`uwo` 레이아웃 파서가 새로 필요합니다.** 다만 `RawSheet`가 이름 영역을 들고 오게 하는 것은 임포터 쪽 일입니다|
|`strkey`|`rescue`의 `ConfigTable`과 같은 상황 — 합성 `Index`를 만들고 원래 키를 보조 인덱스로 강등하면 됩니다|
|`key:min~max`|우리에게 없지만 §6의 범위 검증이 생기면 그것으로 표현됩니다|
|`-` = 없음|파서 옵션 하나 (`rescue`의 `IntNoneValue`와 같은 자리)|
|빈 이름 컬럼|`rescue`의 컬럼 제외 규칙과 같습니다|

> **가장 값이 큰 순서는 「중첩 컬럼 → 컬럼 제약 → 다중 대상 참조」입니다.**
> 앞의 하나는 없으면 생성되는 API가 시트와 다른 모양이 되고, 뒤의 둘은 없으면 **바꿀 이유가 없어집니다.**

### 중첩 컬럼을 어디에 넣는가 — 파급 범위는 처음 본 것보다 작습니다

코드를 읽고 나서 바뀐 판단입니다. 처음에는 바이너리 형식과 13개 리더까지 따라온다고 봤는데, **둘 다 그대로 둘 수 있습니다.**

근거가 셋입니다.

1. **익스포터와 13개 생성기가 보는 단위는 `Field`가 아니라 [`SerialField`](../src/Models/SerialField.cs)입니다** — 「연번이 붙은 컬럼들을 배열 하나로 접은 그룹」. 중첩 필드는 그 그룹의 **원소 타입이 스칼라에서 레코드로 넓어진 것**입니다. 새 개념이 아니라 있는 개념의 일반화입니다.
2. **와이어에는 새 모양이 필요 없습니다.** 컬럼 지향 형식이므로 `character[0..1]["Id"]`는 「길이 2인 고정 배열 컬럼 `Character.Id`」 하나이고, `["Name"]`이 또 하나입니다. 즉 **AoS를 SoA로 저장**하는 것이고, `KindFixedArray`가 이미 그것입니다. 멤버마다 별도 컬럼이라 런렝스·딕셔너리 인코딩도 그대로 걸리고, 멤버를 추가하는 것은 컬럼 태그가 하나 늘는 **가산적 변경**입니다.
3. **`lib/`의 리더 13개는 손대지 않습니다.** 생성되는 읽기 루프는 컬럼을 태그로 분기해 `record.<필드>[j]`에 대입하는 형태이고(`read_kind == 'serial'`), 중첩은 **대입 대상이 `record.<그룹>[j].<멤버>`로 바뀌는 것**이 전부입니다. 리더의 디코드 원시연산은 그대로입니다.

그래서 실제로 건드리는 것은 `Model`·뷰·**13개 테이블 템플릿**·JSON/HTML 익스포터·픽스처입니다. 형식 버전을 올리지 않으므로 스펙과 스큐 게이트도 그대로입니다.

### 실제로 쓰이는 중첩 모양은 셋뿐입니다

615개 테이블의 `:type` 트리를 전수 조사한 결과입니다. **최대 깊이 3, 깊이 3은 리프 4개뿐**입니다.

|모양|리프 수|예|
|--|--|--|
|배열 안에 레코드 (`array>object`)|955|`character[0]["Id"]`|
|스칼라 배열 (`array`)|410|`patrolBuilding[0]`|
|이름 있는 레코드 (`object`)|210|`pos["x"]`|
|배열>레코드>레코드|4|`ConstellationMiniGame.star[].position.x`|
|배열의 배열|2|—|
|레코드 안의 배열|2|—|

**앞의 셋이 1,575/1,583 = 99.5%입니다.** 그 셋만 먼저 지원하고 나머지 8개는 명시적 오류로 두면,
전체의 1%도 안 되는 모양 때문에 재귀 일반화를 먼저 할 필요가 없습니다. 「배열의 배열」은
[지금도 명시적으로 거부](../src/Models/Table.cs)하는 모양이라 그 판단이 이미 서 있습니다.

## 7. 원본 데이터·설정에서 눈에 띈 것

도구와 무관하게 uwo 쪽에 돌려줄 만한 것들입니다.

1. **`UWO_기후.xlsx` (195.3 MiB) 에서 익스포트되는 테이블이 없습니다.** 워크북 범위 정의된 이름이 둘인데,
   하나는 `ShipPartShape = #REF!`(깨진 참조)이고 다른 하나는 `ShipBodyShape = WeatherWind!$A$1:$P$50` —
   **이름은 선박 외형인데 가리키는 것은 기후 시트**입니다. `UWO_선박외형.xlsx`에서 시트를 복사할 때
   이름 정의가 따라온 흔적으로 보입니다. 입력 전체의 절반을 차지하는 파일입니다.

2. **`:requireedInObject` 오타가 3개 테이블에 있습니다.** `cms/validation/validator.lua`의 제네릭 검사기는
   `:requiredInObject`만 보므로, **그 3개 테이블의 중첩 필수값 검사가 조용히 돌지 않고 있습니다.**
   (정상 표기는 216개 테이블에 있습니다.)

3. **`:assets` 2개** — 정식 표기는 `:asset`(89개)입니다. 같은 이유로 에셋 존재 검사가 안 돕니다.

4. **라이브 메인 워크북이 `.xlsb`입니다.** `XWorkbook.WarnIfSaferTwinExists`가 이미 경고하고 있듯,
   `.xlsb`는 ACE OLEDB로 읽혀 **긴 텍스트가 255자에서 잘릴 수 있습니다.** `text` 컬럼 580개가 이 경로를 지납니다.
   덧붙여 `.xlsx`(EPPlus)와 `.xlsb`(ACE)는 **정의된 이름을 열거하는 범위가 다를 수 있어**,
   같은 워크북을 어느 확장자로 저장했는지에 따라 익스포트되는 테이블 집합이 달라질 수 있습니다.

5. **데이터 소스가 아닌 워크북이 섞여 있습니다.** `밸런스조정패널.xlsx`(10.6 MiB), `발견물 관리 시트.xlsx`,
   `타일 정보 보기.xlsb`는 익스포트 대상 이름이 하나도 없는 작업용 워크북입니다.
   `(사용종료백업)` 두 개(61.6 MiB)도 그렇습니다. 우리 쪽에서는 `#` 접두나 `ExcludeSheets`로 명시해야 합니다.

### 산출물 대비를 어떻게 할 것인가

바이트 비교는 불가능합니다. 두 JSON의 모양이 다릅니다.

```jsonc
// uwo — id로 키를 잡은 객체 + 맨 앞에 스키마 블록
{ ":Weather": { ":type": {…}, ":min": {…} },
  "Weather":  { "13200000": { "id": 13200000, "name": "맑음", … } } }

// sheetman — 행의 배열
[ { "id": 13200000, "name": "맑음", … } ]
```

그래서 **행 단위·필드 단위로 값을 맞춰보는 대조기**가 필요합니다. 확인해야 할 것은 세 가지입니다.

- 테이블 집합과 행 집합이 같은가 (`-`로 빠진 프로퍼티, `#` 주석 행, 키 대역 밖 행)
- 값이 같은가 — 특히 `number`(정수/실수 판정), `bit`(2진 → 정수), `text`(`#` 떼기)
- 중첩 구조가 같은 모양으로 접혔는가

**대조기는 정답지가 있는 동안에만 쓸 수 있습니다.** uwo 쪽 익스포트를 계속 돌릴 수 있어야 하므로,
[samples/uwo/](../samples/uwo/)는 사본이고 원본 `C:\work\uwo\game\cms\xls`는 그대로 두었습니다.
