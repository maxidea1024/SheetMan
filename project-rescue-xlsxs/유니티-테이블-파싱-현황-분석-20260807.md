# 유니티 클라이언트의 테이블 파싱 현황 분석

**작성일** 2026-08-07 · **대상** rescue 프로젝트 Unity 클라이언트
**조사 범위** `GoogleSheetsManagerEditor.cs`, `TableEnumSheetUtility.cs`, `DataManager.cs`, `Assets/Scripts/Data/Tables/*.cs` (생성물), `Assets/Data/GoogleSheets/*.csv` (2026-08-03~07 스냅샷)

> SheetMan 구현과 무관한, **그쪽 파이프라인 자체에 대한 분석**입니다. 나중에 개선점을 찾을 때 쓰라고 남깁니다.
>
> 아래 수치는 전부 **실측**입니다. 생성된 68개 클래스에서 가드 값·컬럼 인덱스·타입별 파싱 코드를 추출해, 클라이언트에 들어 있는 CSV에 그대로 재현해 돌린 결과입니다.

## 1. 파이프라인

```
Google 스프레드시트
   │  export?format=csv&gid=…   (WebClient, 서비스계정 Bearer 토큰은 있으면 첨부)
   ▼
Assets/Data/GoogleSheets/{Table}.csv          ← 다운로드 산출물, 저장소에 커밋됨
   │
   ├─ [에디터] GoogleSheetsManagerEditor.GenerateClassCodeFromCsv
   │     └→ Assets/Scripts/Data/Tables/{Table}.cs   (필드 선언 + FromCsvLine)
   │
   └─ [에디터] TableEnumSheetUtility.GenerateCodeFromCsv   (TableEnums.csv 전용)
         └→ Assets/Scripts/Data/Enums/TableEnums.cs
   ▼
[런타임] Addressables 라벨 "GameData" → 텍스트
   └→ DataManager.ParseAllData → ParseTable<T> → {T}.FromCsvLine
        └→ Dictionary<int,T> / Dictionary<string,T>
```

**등록 목록이 유일한 대상 정의**입니다. `Assets/Editor/GoogleSheetsConfig.asset`에 스프레드시트별 시트 목록이 있고, 여기 적힌 **68개**만 다운로드·생성·로드됩니다. 시트 자체에는 대상 여부를 나타내는 표시가 없습니다.

## 2. 테이블 파싱 — 정확한 동작

### 2.1 시트 형식

```
row 1   컬럼 설명       ← `#`/`//`로 시작하거나 [skip]/[ignore] 포함 시 컬럼 제외
row 2   컬럼 이름       ← `_`로 시작하면 컬럼 제외
row 3   컬럼 타입       ← `-`/`ignore`/`skip`이면 컬럼 제외
row 4~  데이터
```

### 2.2 컬럼 포함 규칙 (`ShouldIncludeColumn`)

에디터에서만 판정하고, 그 결과가 **생성 코드에 인덱스로 고정**됩니다.

|조건|결과|
|--|--|
|이름 또는 타입이 빈 칸|제외|
|설명이 `#` 또는 `//`로 시작|제외|
|설명에 `[skip]` 또는 `[ignore]` 포함|제외|
|이름이 `_`로 시작|제외|
|타입이 `-`, `ignore`, `skip`|제외|

포함된 컬럼만 필드로 선언되고, 제외된 컬럼의 인덱스는 **건너뛴 채 원본 위치 그대로** 참조됩니다. 예를 들어 `CharacterTable`은 2번째 컬럼(`#한글이름`)이 제외되어 `TitleName = values[2]`로 생성됩니다.

### 2.3 타입 매핑 (`ConvertToUnityType`)

|시트 표기|C# 타입|파싱 코드|
|--|--|--|
|`int`|`int`|`int.Parse(values[i])`|
|`long`|`long`|`long.Parse(values[i])`|
|`float`|`float`|`float.Parse(values[i])`|
|`bool`|`bool`|`bool.Parse(values[i])`|
|`string`|`string`|`values[i]` (그대로)|
|`intArray`|`int[]`|`ConvertAll(values[i].Split(';'), int.Parse)`|
|`floatArray`|`float[]`|`ConvertAll(values[i].Split(';'), float.Parse)`|
|`stringArray`|`string[]`|`values[i].Split(';')`|
|`enum:Name`|`Name`|`System.Enum.Parse<Name>(values[i])`|
|**그 외 전부**|`string`|`values[i]`|

대소문자는 무시합니다(`Int`, `IntArray`, `Intarray` 모두 인식).

### 2.4 행 처리 (`DataManager.ParseTable<T>`)

```
csvData.Split('\n')  →  3줄 미만이면 테이블 전체 포기 (LogError)
targetDict.Clear()
for i = 3 .. 끝:
    빈 줄이면 건너뜀
    IsRowSkipped(line) 이면 건너뜀
    data = T.FromCsvLine(line)
    if data != null:  targetDict[getId(data)] = data
```

`IsRowSkipped`는 **첫 번째 콤마 필드**만 봅니다 — `#`/`//`로 시작하거나 `[skip]`/`[ignore]`를 포함하면 주석 행으로 간주합니다.

### 2.5 행 파싱 (생성된 `FromCsvLine`)

```csharp
csvLine = csvLine.TrimEnd('\r');
string[] values = csvLine.Split(',');
if (values.Length < N) { LogWarning; return null; }   // N = 헤더 전체 컬럼 수(제외분 포함)
try   { …필드별 Parse… }
catch { LogError; return null; }
```

**메서드 전체가 try/catch 하나로 묶여 있습니다.** 셀 하나가 실패하면 `null`이 반환되고, 호출부는 그 행을 사전에 넣지 않습니다 — **한 칸 때문에 행 전체가 사라집니다.**

## 3. 오류 처리 현황

|상황|결과|알림|
|--|--|--|
|CSV가 3줄 미만|테이블 전체 미로드|`LogError`|
|컬럼 수 부족|해당 행 폐기|`LogWarning`|
|셀 파싱 실패 (형식·범위·enum 라벨)|**행 전체** 폐기|`LogError`|
|**Id 중복**|**나중 행이 앞 행을 덮어씀**|**없음**|
|등록됐는데 데이터가 안 실림|테이블 미로드|`LogWarning`|
|매핑표에 없는 타입 표기|`string`으로 취급|**없음**|
|다운로드 실패 (429 외)|해당 시트만 건너뜀|`LogError`|

두 줄만 무음입니다. 그리고 **로드 실패가 게임을 멈추지 않습니다** — 사전이 비었거나 행이 빠진 채로 실행이 계속되고, 증상은 나중에 다른 곳에서 `null` 참조나 "안 나오는 콘텐츠"로 나타납니다.

`Debug.Log` 계열은 릴리스 빌드에서 스트립될 수 있으므로, 위 경고들은 **실기기에서는 대체로 보이지 않습니다.**

## 4. 지금 실제로 일어나고 있는 일

68개 테이블, 데이터 **109,288행**을 재현한 결과입니다.

|항목|결과|
|--|--|
|컬럼 수 부족으로 폐기|**0행**|
|셀 파싱 실패로 폐기|**0행**|
|`IsRowSkipped`로 건너뜀|**0행**|
|**Id 중복으로 덮어써짐**|**56행** (`ArtifactLevelTable`)|
|생성 클래스와 현재 CSV의 불일치|**없음** (68개 전부 동기화 상태)|

### 유일한 실제 손실: `ArtifactLevelTable`

Id `45`가 **57번** 반복됩니다(레벨 45~101 구간). 101행이 들어가지만 사전에는 **45개 키만 남고**, 최종적으로 Id 45에는 마지막 행의 수치가 들어 있습니다.

**로그는 한 줄도 남지 않습니다.** `targetDict[id] = data`가 조용히 덮어쓰기 때문입니다. 레벨 46~101을 조회하면 없는 키이고, 45를 조회하면 101의 값이 나옵니다.

> 참고: 저희가 받은 xlsx 스냅샷에는 `SkillTable`의 빈 Id 9행과 `CollectionGroupTable`의 `#9`/`#10` 행도 있었는데, 클라이언트의 CSV(08-06, 08-07 다운로드분)에서는 정리되어 있습니다. `ArtifactLevelTable`만 08-03 스냅샷 그대로입니다.

## 5. 취약점

번호는 우선순위가 아니라 식별용입니다. **[현재]** 는 지금 증상이 있는 것, **[잠복]** 은 조건이 갖춰지면 터지는 것입니다.

### V1. CSV 인용을 지원하지 않음 — [잠복, 조건 근접]

`Split(',')`로 자릅니다. RFC 4180 인용(`"a, b"`)을 모릅니다. 콤마가 든 셀 하나가 그 행의 **뒤쪽 컬럼 전부를 한 칸씩 밀어버립니다.**

현재 인용 콤마가 든 행이 **40행** 있습니다.

|파일|행 수|위치|
|--|--|--|
|`SeasonShopTable.csv`|36|`Description` (맨 끝, `#` 제외 컬럼)|
|`SFXSoundTable.csv`|3|`Description` (맨 끝, `#` 제외 컬럼)|
|`ShopInfoTable.csv`|1|`Description` (맨 끝, `#` 제외 컬럼)|

**지금 사고가 안 나는 이유는 우연입니다.** 세 경우 모두 콤마가 마지막 컬럼에 있고 그 컬럼이 `#`로 제외되어 파싱 인덱스 범위 밖이기 때문입니다. 기획자가 앞쪽 문자열 컬럼에 콤마를 한 번 찍는 순간, 그 행부터 컬럼이 밀리고 → 타입이 안 맞으면 행이 폐기되고 → **타입이 우연히 맞으면 조용히 다른 값이 들어갑니다.**

같은 저장소 안에 **제대로 된 CSV 파서가 이미 있습니다.** `TableEnumSheetUtility.ParseCsvLine`은 인용과 이스케이프(`""`)를 정확히 처리합니다. enum 경로만 그것을 쓰고, 테이블 경로는 쓰지 않습니다.

> 개선 후보: `ParseCsvLine`을 공용으로 빼서 테이블 경로(에디터 생성기, `DataManager`, 생성 코드)에서도 쓰기.

### V2. 컬럼 인덱스 하드코딩 + 재생성 강제 없음 — [잠복]

생성된 클래스는 `values[7]`처럼 **생성 시점의 위치**를 들고 있습니다. 시트에 컬럼을 중간에 끼우거나 지운 뒤 클래스를 재생성하지 않으면, 그 뒤 컬럼이 전부 한 칸씩 어긋난 채로 읽힙니다.

- 타입이 안 맞으면 → 행 전체 폐기 (`LogError`)
- **타입이 맞으면 → 조용히 다른 컬럼의 값이 들어감**

CSV와 클래스의 버전이 같은지 확인하는 장치가 없습니다. CSV는 커밋되고 클래스도 커밋되지만, 둘이 짝인지는 아무도 검사하지 않습니다.

**현재 상태는 정상입니다** — 68개 전부 지금 CSV로 재생성한 결과와 일치하는 것을 확인했습니다. 다만 그것을 지켜주는 것은 규율뿐입니다.

> 개선 후보: 헤더 2·3행의 해시를 생성 코드에 상수로 박고, `ParseTable`이 로드한 CSV의 해시와 비교해 다르면 에러.

### V3. Id 중복이 완전히 무음 — [현재]

`targetDict[id] = data`. 경고도 오류도 없습니다. 4장의 56행이 이 상태입니다.

> 개선 후보: `if (!targetDict.TryAdd(id, data)) Debug.LogError(...)` 한 줄.

### V4. 셀 하나의 실패가 행 전체를 삼킴 — [잠복]

`FromCsvLine` 전체가 try/catch 하나입니다. 설명 문구 하나가 잘못돼도 그 캐릭터/스테이지 행이 통째로 없어집니다. 게임은 그 행이 원래 없었던 것처럼 계속 돌아갑니다.

> 개선 후보: 필드별로 `TryParse`하고, 실패한 칸만 기본값 + 어느 테이블 어느 행 어느 컬럼인지 로그. 또는 반대로 — 실패 시 로드 전체를 중단.

### V5. 문화권 의존 파싱 — [잠복, 기기 의존]

`int.Parse`, `long.Parse`, `float.Parse`, `bool.Parse` 어디에도 `CultureInfo`가 지정되어 있지 않아 **기기의 현재 문화권**을 따릅니다.

프로젝트 전체에서 `InvariantCulture`를 쓰는 곳은 `Utility/ExpressionParser.cs` 세 군데뿐입니다. 테이블 파싱 경로에는 없습니다.

소수점을 콤마로 쓰는 로케일(독일어, 프랑스어, 대부분의 유럽·남미)로 설정된 기기에서 `float.Parse("1.5")`는 **실패하거나 15가 됩니다.** 실패하면 V4에 의해 행 전체가 사라집니다. 현재 `float` 컬럼은 133개입니다.

> 개선 후보: 전부 `CultureInfo.InvariantCulture` 명시. 또는 앱 시작 시 `CultureInfo.DefaultThreadCurrentCulture = CultureInfo.InvariantCulture`.

### V6. `Enum.Parse`의 두 가지 성질 — [잠복]

`System.Enum.Parse<T>(string)`은:

1. **대소문자를 구분합니다.** 시트에 `melee`라 적고 라벨이 `Melee`면 예외 → V4로 행 폐기.
2. **정의되지 않은 숫자를 그대로 통과시킵니다.** `Enum.Parse<GradeType>("999")`는 성공하고 `(GradeType)999`가 들어갑니다. 검증 없이 통과하는 유일한 경로입니다.

현재 데이터에는 두 경우 모두 **0건**입니다(147개 enum 컬럼 전수 확인).

> 개선 후보: `Enum.TryParse<T>(s, ignoreCase: true, out v) && Enum.IsDefined(typeof(T), v)`.

### V7. enum 값이 선언 순서 암묵값 — [구조적]

`TableEnums.cs`는 값을 적지 않습니다.

```csharp
public enum GradeType
{
    N,      // 0
    R,      // 1
    SR      // 2
}
```

시트에서 라벨을 **지우거나 순서를 바꾸면** 저장된 정수의 의미가 바뀝니다. 서버에 등급이 정수로 저장돼 있거나 세이브 데이터에 들어 있다면 그때 어긋납니다. 0번 라벨이 무엇인지도 시트 순서에 달려 있어서, 기본값으로 초기화된 필드가 무엇을 뜻하는지 시트를 봐야 알 수 있습니다.

> 개선 후보: 시트에 값 컬럼을 두고 명시적으로 생성. 최소한 "라벨은 끝에만 추가한다"를 규칙으로 문서화.

### V8. 가드가 제외 컬럼까지 세고 있음 — [잠복]

`if (values.Length < N)`의 `N`은 헤더 2행을 콤마로 자른 **전체 개수**(제외 컬럼 포함)입니다. 맨 끝 `#` 컬럼이 전부 비어서 CSV가 짧게 나오면, 실제로 필요한 값은 다 있는데도 행이 폐기됩니다.

현재 0행이지만, Google의 CSV export는 후행 빈 칸을 채워주기 때문에 안 걸리는 것입니다.

> 개선 후보: `N`을 실제로 참조하는 최대 인덱스 + 1로.

### V9. 참조 무결성 검사 없음 — [구조적]

`Item_ID`, `Condition_ID`, `Basic_Attack1` 같은 컬럼은 다른 테이블의 Id지만, 그 Id가 실재하는지 로드 시점에 아무도 확인하지 않습니다. 오타나 삭제된 Id는 런타임에 조회가 `null`을 반환할 때 비로소 드러납니다.

### V10. `IsRowSkipped`도 naive split — [잠복]

`line.Split(',')[0]`로 첫 칸을 얻으므로, 첫 컬럼이 인용된 문자열이면 판정이 어긋납니다. 현재 첫 컬럼은 전부 Id(정수)라 문제없습니다.

### V11. 다운로드가 동기 + 시트당 1초 고정 대기 — [경미]

`DownloadAllSheetsSync`가 `Thread.Sleep(1000)`을 시트마다 겁니다. 68개면 최소 68초, 그동안 에디터가 멈춥니다. 429 재시도는 지수 백오프로 처리하고 있으므로 고정 대기는 보수적인 여유분입니다.

### V12. `ConfigTable.GetValue<T>`의 조용한 기본값 — [잠복]

```csharp
try { return (T)System.Convert.ChangeType(DefaultValue, typeof(T)); }
catch { Debug.LogError(...); return default(T); }
```

변환 실패 시 `default(T)`(숫자면 0)를 반환합니다. 호출부가 그것을 유효한 설정값과 구분할 방법이 없습니다. `Convert.ChangeType`도 문화권을 따릅니다(V5와 같은 문제).

**조건이 갖춰지면 터지는 것**

- 앞쪽 컬럼에 콤마 하나 → 그 행부터 컬럼 밀림 (V1) — 이미 40행이 인용 콤마를 갖고 있고, 위치가 우연히 안전할 뿐
- 컬럼 삽입/삭제 후 클래스 재생성 누락 → 조용히 다른 값 (V2)
- 유럽권 로케일 기기 → float 컬럼 133개가 전부 위험 (V5)
- enum 라벨 삭제·순서 변경 → 저장된 값의 의미 변경 (V7)

**성격**

파이프라인 전체가 **실패해도 진행하는 쪽**으로 설계되어 있습니다. 행 하나가 안 읽히면 그 행 없이, 테이블 하나가 안 읽히면 그 테이블 없이 게임이 실행됩니다. 개발 중에는 편하지만, **잘못된 데이터와 정상 데이터를 구분할 수 있는 시점이 로드 순간뿐인데 그때 멈추지 않으므로**, 증상은 항상 원인에서 멀리 떨어진 곳에서 나타납니다.

가장 값싼 개선 셋을 고른다면:

1. `TryAdd` — Id 중복을 오류로 (한 줄, V3)
2. `CultureInfo.InvariantCulture` 명시 — 기기 로케일 의존 제거 (V5)
3. 이미 있는 `ParseCsvLine`을 테이블 경로에서도 사용 (V1)

## 부록. 조사 방법

생성된 68개 클래스에서 정규식으로 다음을 추출했습니다.

- `values.Length < N` 가드 값
- 필드별 `values[i]` 인덱스와 파싱 종류(`int.Parse` / `Enum.Parse<T>` / `Split(';')` / 원문)
- `TableEnums.cs`의 enum별 라벨 목록

그 다음 `Assets/Data/GoogleSheets/*.csv`를 `DataManager.ParseTable`과 동일한 순서로 읽어 (3줄 헤더 건너뛰기 → 빈 줄 → `IsRowSkipped` → `Split(',')` → 가드 → 필드별 파싱 → 사전 삽입) 각 단계의 결과를 셌습니다. .NET의 `int.Parse` / `float.Parse` / `bool.Parse` / `Enum.Parse` 수용 범위를 그대로 흉내 냈습니다.

동기화 검사는 `GenerateClassCodeFromCsv`를 재구현해 현재 CSV로 클래스를 다시 만들고, 커밋된 클래스의 필드 선언·인덱스·가드와 비교했습니다.
